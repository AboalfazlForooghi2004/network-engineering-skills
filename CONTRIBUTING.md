# Contributing

Thank you for contributing to `network-engineering-skills`.

## Scope

Contributions should improve the accuracy, safety, clarity, or practical usefulness of a network-engineering skill.

## Quality bar

- Write skill instructions in clear, concise English.
- Prefer vendor-accurate guidance over generic command lists.
- Keep automation read-only or dry-run by default.
- Never include credentials, private keys, tokens, or real infrastructure secrets.
- Require explicit confirmation before destructive or production-impacting actions.
- Include prerequisites, validation steps, failure handling, and rollback guidance.
- Do not claim a command is portable across platforms unless it has been verified.

## Pull requests

Every pull request should explain:

1. What problem the skill solves.
2. Which platforms and tools it covers.
3. How the skill was tested.
4. What safety boundaries apply.
5. Whether the change affects existing workflows.
